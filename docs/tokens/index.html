设计令牌

216 个令牌的三层结构、两套主题，以及为什么界面不该攒灰值。

设计令牌

ui/css/tokens.css 是唯一允许出现字面量的文件。目前共 216 个令牌定义，分三层：

层数量内容引用约束
Primitive111亮度阶、墨阶、表面阶、功能色、间距阶（25 个）、圆角阶（9 个）、字体、动效、层级、浮层阴影不带语义，禁止跨层直接引用
Semantic41--c-* 语义别名组件层唯一允许引用的层
Role24组件固有尺寸（rail 宽、弹窗宽、栅格最小列宽…）只属于某个组件

浅色主题不新增层级，而是在 [data-theme="light"] 下覆写 40 个语义令牌（41 个里 有唯一一个刻意不覆写，见下），所以 216 = 176（三层）+ 40（浅色那次覆写）。

--c-* 全部指向 Primitive，组件层只写 var(--c-surface-3) 这种语义引用。 校验方式：把 components.css 和 pages.css 里的 #hex / rgba() / px 统个数——都是 0。

表面阶：用「白 + 透明度」代替灰值

深色界面最容易失控的地方是灰色。#1d2026、#262a31、#16181c 攒到十几个之后， 没人还分得清某个位置该用哪一个。PortButler 的做法是不发散灰值——表面一律用 「白色 + 透明度」，7 级递进，语义就是「有多浮起」（下表取值是深色那套）：

令牌深色取值语义
--c-surface-1rgba(255,255,255,.04)静置：卡片 / 列表项
--c-surface-2rgba(255,255,255,.06)轻 hover：rail 图标
--c-surface-3rgba(255,255,255,.08)hover：卡片内按钮 / chip / 徽标
--c-surface-4rgba(255,255,255,.10)选中：rail 图标 / 页签药丸
--c-surface-5rgba(255,255,255,.12)浮层：toast
--c-surface-6rgba(255,255,255,.14)强调 hover：按钮 / 模板卡选中
--c-surface-7rgba(255,255,255,.16)chip hover

交互态一律「往更高一阶走」，不需要为每个组件单独调色。因为透明度叠加在深色底上， 同一阶在不同底上的观感也自然协调——这是灰值做不到的。

浅色下这套方向反过来：--c-surface-1 是实体白（卡片浮在浅灰应用底上）， --c-surface-2…7 才是「黑 + 透明度」逐级压深。命名保持不变，换的只是值。 主按钮不再占用表面阶——它需要「底色 + 前景」成对声明，见下。

实体底 / 描边 / 填充 / 浮起 / 文字

--c-app-bg  var(--k800)  #16181c   应用底
--c-rail    var(--k900)  #111317   侧栏（比应用底更沉）
--c-modal   var(--k700)  #1d2026   弹窗底
--c-tooltip var(--k600)  #262a31   悬浮气泡

--c-border-field  rgba(255,255,255,.09)   控件边界（输入框 / 日志块 / 图标选择框）
--c-border-float  rgba(255,255,255,.09)   浮层边界（弹窗 / 气泡）
--c-border-focus  rgba(255,255,255,.30)   输入框聚焦
--c-ring          rgba(255,255,255,.38)   键盘焦点环
--c-toast-ring    transparent              toast 外描边（浅色才需要）

--c-fill-field    var(--c-surface-1)      控件填充
--c-shadow-lift   none                    静置浮起（菜单 / 气泡）
--c-shadow-float  none                    浮层（弹窗 / toast）

--c-text    rgba(255,255,255,.92)   主文字
--c-text-2  rgba(255,255,255,.50)   次要文字与图标
--c-text-3  rgba(255,255,255,.32)   元信息 / 占位
--c-text-inv #ffffff                强调底上的反白

为什么把描边拆成两个名字（--c-border-field / --c-border-float）， 而不是一个 --c-border：浅色主题里这两者的命运完全不同。控件边界改由填充色承担 （--c-fill-field 给一层极浅灰底），浮层边界则连填充都省了、直接换成一圈柔和阴影。 一个名字表达不了两种处置方式。

结构分割线整体不存在了。 原来 rail 右侧、页签底部、卡片四周、表格行间各有一圈 --hairline 描边，浅色下这些线会把界面切碎。现在层级一律由色差表达： #eaeaed 的侧栏挨着 #f3f4f5 的内容区，白卡片浮在浅灰底上——不需要任何线来分界。

焦点环刻意用灰阶而不是系统默认的蓝色圈——蓝色在整套灰阶里非常突兀。 文本框是例外：点输入框时浏览器也会命中 :focus-visible，套上焦点环会多出一圈描边， 所以输入框的聚焦反馈走 .input:focus 的边框变色，不套环。

主操作按钮：底色与前景成对

--c-primary-bg       深色 var(--w16)      浅色 #161616（近黑）
--c-primary-bg-hover 深色 var(--w24)      浅色 rgba(0,0,0,.82)
--c-primary-fg       深色 var(--c-text)   浅色 #ffffff（反白）

一屏只有一个主操作（「开始打包」「保存」「发布」），它必须和普通按钮一眼可分。 深色下这个差异可以靠「比普通按钮亮一阶」表达，浅色下不行——浅灰底上再叠浅灰就是没有。 所以浅色直接把主按钮做成近黑实底 + 反白字，这也是参考稿的做法。

成对声明（底色 + 前景）而不是只换底色：反白字只有在深色底上才成立， 两者必须一起变，否则浅色主题会出现「白字白底」。

开关：滑钮纯白，轨道才换色

--c-switch-off   深色 var(--w12)      浅色 var(--bk12)
--c-switch-on    深色 var(--w24)      浅色 var(--lt-primary)   /* 近黑 */
--c-switch-knob  #ffffff               —— 只在 :root 声明，浅色段里没有它

--c-switch-knob 是全套里唯一不被浅色覆写的语义令牌。理由和主按钮同源： 深色的「开」是「比关更亮一阶」，浅色照镜像走就成了「比关更深的灰」——在浅灰底上立不住。 所以浅色的开态直接跳到近黑。而滑钮要是跟着主题变深，在近黑轨道上就看不见了， 于是它两套主题都保持纯白，[data-theme="light"] 里干脆不出现这个名字。

状态色：整个界面只有三种彩色

令牌深色取值用在哪
--c-okrgba(120,220,150,.90)运行状态点、成功提示
--c-warnrgba(255,200,120,.75)剩余时间不足的徽标
--c-danger#ff8a8a发布失败、删除确认

浅色版相应压深（--c-ok → rgba(20,128,62,.95)、--c-danger → #c0392b）， 否则亮底上的浅绿浅红基本看不见。

除此之外界面完全无彩色。「运行中」那个绿点是全套里唯一使用彩色辉光的地方 （--c-ok-glow），因为它需要在小尺寸下被一眼扫到。

/* 一枚色块。底色直接用令牌，所以它显示什么就是应用里跑什么 */
function Swatch({ token }: { token: string }) {
  return (
    <span
      style={{
        width: 30,
        height: 20,
        flex: "none",
        borderRadius: "var(--r-6)",
        border: "var(--hairline) solid var(--c-border-float)",
        background: `var(${token})`,
      }}
    />
  );
}

function Row({ t }: { t: Token }) {
  return (
    <div style={{ display: "flex", alignItems: "center", gap: 10 }}>
      <Swatch token={t.name} />
      {/* 浅色取值：套一层 data-theme 就换了一套值，令牌名完全一样 */}
      <span
        data-theme="light"
        style={{
          display: "inline-flex",
          padding: 3,
          borderRadius: "var(--r-8)",
          background: "var(--c-app-bg)",
          outline: "var(--hairline) solid var(--c-border-float)",
        }}
      >
        <Swatch token={t.name} />
      </span>
      <code style={{ fontSize: 11, color: "var(--c-text)", minWidth: 150 }}>{t.name}</code>
      <span style={{ fontSize: 11, color: "var(--c-text-3)" }}>{t.note}</span>
    </div>
  );
}

function Swatches({ list }: { list: Token[] }) {
  return (
    <div style={{ display: "grid", gap: 9 }}>
      {list.map((t) => (
        <Row key={t.name} t={t} />
      ))}
    </div>
  );
}

function Section({ title, children }: { title: string; children: React.ReactNode }) {
  return (
    <div>
      <span className="pb-spec">{title}</span>
      {children}
    </div>
  );
}

间距与尺寸：命名即像素值

--px-1: 1px;  --px-2: 2px;  --px-4: 4px;  --px-6: 6px;  --px-8: 8px;
--px-10: 10px; --px-12: 12px; --px-14: 14px; --px-16: 16px; --px-20: 20px;
--px-24: 24px; --px-26: 26px; --px-34: 34px; --px-40: 40px; --px-46: 46px;
--px-90: 90px;

共 25 个，命名即像素值——--px-8 就是 8px，不做 --space-md 这类二次换算。 好处是逐像素可校验：读代码时看到 var(--px-13)，不需要跳去定义文件就知道是 13px。

只收录当前在用的值。需要新尺寸时先看语义层有没有能复用的，确实没有才往 Primitive 加。

角色层：组件固有尺寸

--rail-w: 64px;   --rail-btn: 40px;  --icon: 20px;    --icon-stroke: 1.6;
--dot: 7px;       --spinner: 10px;   --checkbox: 14px;
--modal-w: 440px; --modal-w-publish: 470px; --modal-w-wide: 560px;
--list-max-h: 390px;    --build-log-h: 240px;   --icon-pick: 48px;
--about-icon: 64px;     /* 关于页的应用图标 */
--switch-w: 36px;  --switch-h: 20px;  --switch-knob: 16px;
--grid-min: 320px;      /* 项目卡片 */
--grid-min-page: 340px; /* 发布记录页两列起 */
--field-slim-w: 110px;  /* 端口这种窄字段 */

这些数字是「看起来正好」调出来的，不是从某一阶推出来的——rail 就是 64px， 圆角按钮就是 40×40，弹窗按内容分三档宽度。所以它们放在 Role 层而不是 Semantic 层： 不属于任何可枚举的视觉阶梯，只属于那个组件。

两套主题：换的是值，不是选择器

深色为默认（写在 :root），浅色在 [data-theme="light"] 下只重绑第 2 层：

:root {
  /* 第 1 层：两套原始值并存，命名分开互不干扰 */
  --w20:  rgba(255, 255, 255, .20);  /* 深色用「白 + 透明度」在暗底上提亮 */
  --bk30: rgba(0, 0, 0, .280);       /* 浅色镜像地用「黑 + 透明度」在亮底上压深 */
  --k800: #16181c;                   /* 深色实体底 */
  --lt-app: #f3f4f5;                 /* 浅色实体底 */

  /* 第 2 层：默认深色 */
  --c-app-bg:  var(--k800);
  --c-surface-1: var(--w4);
}

[data-theme="light"] {
  color-scheme: light;
  /* 只换值：41 个语义令牌里覆写 40 个（例外只有 --c-switch-knob） */
  --c-app-bg:  var(--lt-app);
  --c-surface-1: var(--lt-tip);
  /* … 其余 38 个 */
}

组件层引用的还是那 41 个 --c-*，components.css / pages.css 没有为此新增任何选择器 —— 这是三层结构唯一的价值兑现点。前提是「组件层不出现字面量」这个约束没被破坏， 所以每次改动都该跑一次校验：

node scripts/sync-portbutler-css.mjs --check

四个不能机械镜像的地方

  • 表面阶的方向反了。 深色里「越浮起越亮」，浅色里「越浮起越白」，所以最低那阶 --c-surface-1 在浅色下是实体白（卡片浮在浅灰应用底上），而不是一层黑纱； --c-surface-2…7 才继续用黑透明度递进。
  • 主按钮要反过来走。 深色里主按钮靠「比普通按钮更亮」区分，浅色里这条规律失效—— 浅灰底上叠浅灰等于没有。浅色直接给近黑实底（--lt-primary = #161616）+ 反白字， 于是 --c-primary-bg 与 --c-primary-fg 必须成对重绑。
  • 靠透明度堆出来的「选中底」在浅色下不够深。 页签与 rail 的选中态原本借用表面阶 （深色 w24 亮灰 + 反白字，正好），浅色下同一个值反白字完全压不住。 于是抽出了 --c-accent-bg：深色取 var(--w24)（与改动前逐像素一致）， 浅色取 var(--bk85) 深墨底。同理 toast 在浅色下是白底浮层，需要 --c-toast-ring 给一条边界，而浮层本身改由 --c-shadow-float 找边界。
  • 开关的滑钮两套主题都必须纯白。 这是唯一一个「语义令牌不参与重绑」的例子： 浅色开关的开态是近黑轨道，滑钮跟着变深就看不见了，所以 --c-switch-knob 只在 :root 声明一次。规矩不是「语义层必须在浅色段里出现」，而是「每个令牌 各自判断该不该换」——凑数式覆写反而会造出看不见的控件。
