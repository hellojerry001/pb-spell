删除项目的二次确认：路径展示、可选复选框、失败不关窗。

危险确认 DelBox

删除项目不可逆，所以单独一层确认。这里踩过的坑最多，三个约束都是被逼出来的。

删除项目

客户件量分析2026
/Users/jerry/WorkBuddy/2026-09-08-09-29-54/customer-volume-analysis
文件不会永久删除，而是移到废纸篓 —— 误删可以直接还原。 目录下若还有正在运行的进程，会先被结束。
/**
 * DelBox —— 危险操作二次确认
 * 结构来自 index.html 的 #delModal：`.modal`（440px）> modal-title
 * > del-box（del-name + del-path）> del-opt（复选框）> del-tip > modal-foot。
 *
 * 三条设计约束（都是踩过坑才加的）：
 *   1. 不用原生 confirm()——在 Tauri 里样式割裂且无法承载复选框；
 *   2. 「删文件」是复选框而不是默认行为，默认勾选但可取消；
 *   3. 路径用 user-select:text 放开选中，方便用户核对到底删的是哪个目录。
 */
export function Demo() {
  return (
    <div className="overlay is-open">
      <div className="modal">
        <h3 className="modal-title">删除项目</h3>

        <div className="del-box">
          <div className="del-name">客户件量分析2026</div>
          <div className="del-path">
            /Users/jerry/WorkBuddy/2026-09-08-09-29-54/customer-volume-analysis
          </div>
        </div>

        <label className="del-opt">
          <input type="checkbox" defaultChecked />
          <span>同时删除磁盘上的项目文件夹</span>
        </label>

        <div className="del-tip">
          文件不会永久删除，而是移到废纸篓 —— 误删可以直接还原。
          目录下若还有正在运行的进程，会先被结束。
        </div>

        <div className="modal-foot">
          <button className="btn is-ghost">取消</button>
          <button className="btn is-danger pb-show-hover">删除</button>
        </div>
      </div>
    </div>
  );
}

三个必须这么做的理由

① 不用原生 confirm()。 在 Tauri 的 WebView 里原生弹窗样式完全割裂， 而且它承载不了复选框——而「删不删文件」正是这里最关键的一个选择。

② 「删文件」必须是可取消的复选框。 默认勾选（大多数时候用户确实想连文件一起清掉）， 但取消勾选后只从列表里移除、磁盘文件原封不动。这是「删记录」和「删文件」两件事， 绝不能合并成一个不可选项。

③ 路径要放开选中。 .del-path 上有这一条：

.del-path { user-select: text; }

因为整个应用在 base.css 里设置了 * { user-select: none }（桌面应用的原生感）， 但删除确认里用户需要核对到底删的是哪个目录——很可能想复制路径去 Finder 里看一眼。 所以这里单独把选中放开。

提示随选项变化

.del-tip 的文案不是静态的，syncDelTip() 会跟着复选框与「项目是否正在运行」重算：

function syncDelTip() {
  const withFiles = $("delFiles").checked;
  const live = $("delTip").dataset.live === "1";
  let tip = withFiles
    ? "整个项目文件夹会被移入废纸篓（可从废纸篓还原），不是永久删除。"
    : "只移除这里的记录，磁盘上的文件夹保持原样。";
  if (withFiles && live) tip += "该项目正在运行，会先自动停止再删除。";
  $("delTip").textContent = tip;
}

「会先自动停止」这句只在真的会停进程时才出现——给用户一个确定的预期， 而不是让他猜「删一个正在跑的项目会发生什么」。

失败不关窗

async function confirmDelete() {
  if (delBusy) return;
  const id = delId;
  const withFiles = $("delFiles").checked;

  delBusy = true;
  $("delBtn").disabled = true;
  $("delCancel").disabled = true;
  $("delBtn").textContent = withFiles ? "删除中…" : "移除中…";
  $("delTip").textContent = withFiles ? "正在停止进程并移动文件夹到废纸篓…" : "正在移除记录…";

  try {
    const r = await invoke("delete_project", { id, deleteFiles: withFiles });
    projects = r.list;
    closeModal("delModal");
    renderProjects();
    toast(r.message || "已删除");
  } catch (e) {
    // 失败不关弹窗，把原因留在原处，方便改完重试
    delBusy = false;
    $("delBtn").disabled = false;
    $("delCancel").disabled = false;
    $("delBtn").textContent = "重试";
    $("delTip").textContent = String(e);
  }
  delBusy = false;
  setTimeout(refreshAll, 400);
}

失败时保持弹窗打开、把错误写在 .del-tip 位置、按钮变成「重试」。 关掉弹窗只留一条 toast，用户会完全不知道下一步该做什么。

delBusy 这个标志位同时做了三件事：防重复点击、忙碌期间禁止关闭 （closeDelete() 开头 if (delBusy) return;）、以及撑住整个忙碌态的文案。

文件不会真的被永久删除

后端 projects.rs 的 move_to_trash() 走的是「移到废纸篓」而不是 remove_dir_all：

  • 重名时自动避让（名字 1 / 名字 2）；
  • 跨卷时回退为「递归复制 + 删原目录」；
  • 不调 tell application "Finder" to delete（会触发 TCC 自动化授权弹窗）。

护栏是成对的：保护目录黑名单（/、/Users、/Applications、/Library、/System、$HOME 及一级敏感目录）

  • 深度要求（家目录下至少两级）+ 拒绝符号链接（用 symlink_metadata 判断，因为 canonicalize 会跟随链接，直接把链接指向的目录删掉）。

顺序也是有讲究的：先校验 → 停进程 → 搬迁成功 → 最后才改配置。 这样任何一步失败都不会出现「配置没了但文件还在」的半死状态。
