概览

PortButler 的界面层是怎么组织的：四层样式、三层令牌、渲染工厂与事件委托。

概览

PortButler 是 Tauri 2 桌面应用，界面层是无打包器的静态前端：没有 React、没有构建步骤， ui/ 目录下的 HTML/CSS/JS 在编译期被 brotli 内嵌进二进制。这个文档站负责把这套界面层 拆开、摊平、可视化。

四层样式

样式按「越靠上越抽象」分层，加载顺序不可颠倒：

层文件职责硬性约束
令牌css/tokens.css设计令牌唯一定义源只有这一层允许出现字面量
基础css/base.css盒模型重置、根排版、焦点环、关键帧不含任何具体组件外观
组件css/components.css所有组件的长相零字面量，只引用语义令牌
页面css/pages.css应用外壳与页面组合布局不含组件外观

「零字面量」不是口号——有用脚本实际校验：组件层与页面层里 #hex / rgba() / px 的出现次数都是 0。

三层令牌

Primitive          原始值。调色板与尺寸阶，不带语义，禁止跨层直接引用
    ↓
Semantic  --c-*    语义别名。组件唯一允许引用的层
    ↓
Role               组件固有尺寸（rail 宽 64px、弹窗宽 440/470/560px…）

深色界面最容易失控的地方是灰色阶——#1d2026、#262a31、#16181c 攒到十几个之后没人分得清谁该用谁。 PortButler 的解法是不发散灰值，而是用「白色 + 透明度」建立 7 级表面阶：

--w4:  rgba(255, 255, 255, .04);   /* --c-surface-1 静置 */
--w8:  rgba(255, 255, 255, .08);   /* --c-surface-3 hover */
--w14: rgba(255, 255, 255, .14);   /* --c-surface-6 强调 hover */
--w16: rgba(255, 255, 255, .16);   /* --c-surface-7 chip hover */
--w24: rgba(255, 255, 255, .24);   /* --c-accent-bg 强选中底 */

交互态一律「往更高一阶走」，不需要为每个组件单独调色。这也是为什么整个界面几乎没有彩色—— 层级靠透明度、状态靠极少量点缀色。

这套三层结构唯一的价值兑现点是：以后加浅色主题，只需在 [data-theme="light"] 下重绑第 2 层， 组件层零改动。

渲染工厂与事件委托

动态部分由 js/ui.js 的渲染工厂产出 HTML 字符串：

UI.btn("刷新", { act: "refresh-all" })
// → <button class="btn" data-act="refresh-all">刷新</button>

三条约定：

  • 事件只写 data-act / data-oninput / data-onchange，绝不拼 onclick； 文档级委托层按属性路由到处理器注册表（原来的写法是 34 个全局函数 + 34 处内联 onclick）；
  • 插值一律走 esc()，属性走 dataAttrs()——顺带把潜在的 XSS 面收掉；
  • 类名拼装统一走 cls(...)，不在业务代码里手写 "btn is-ghost" 这类字符串。

这些预览是怎么渲染的

文档站里的预览不是截图，也不是重写一套样式，而是：

  1. scripts/sync-portbutler-css.mjs 把 PortButler 的 tokens.css / components.css / pages.css 逐字节复制到本站（styles/portbutler/），并在编译前自动跑；
  2. 每个示例文件（registry/examples/*.tsx）用与产品完全相同的类名写出结构；
  3. <ComponentPreview name="button" /> 左侧渲染该示例、右侧展示它的源码。

所以「预览里看到的」和「应用里跑的」是同一份 CSS、同一套类名。想知道两边有没有漂移：

node scripts/sync-portbutler-css.mjs --check

base.css 是唯一不参与同步的文件——它含有应用外壳样式（body { display:flex; height:100vh }）， 搬过来会把文档站掀掉。其中真正影响组件观感的部分（焦点环、控件字体重置、.span-all / .push-end） 在 styles/portbutler/preview-scope.css 里以 .pb-preview 为作用域补回了。

主题

PortButler 有深色 / 浅色两套主题，默认深色。切换入口在应用左下角，三档可选： 跟随系统 / 浅色 / 深色。选择记在 localStorage；停在「跟随系统」时会实时响应 系统外观变化，不需要重启。

两套主题共用第 1 层（原始值）与第 3 层（组件固有尺寸），只重绑第 2 层：

:root                 深色（默认）—— 组件引用的那批 --c-*
[data-theme="light"]  浅色       —— 同样那批 --c-*，换一组值

深色靠「白 + 透明度」在暗底上提亮，浅色镜像地靠「黑 + 透明度」在亮底上压深， 所以两套原始值分开命名（--w* / --k* 给深色，--bk* / --lt-* 给浅色），互不干扰。

组件层只多拆了三对语义：加浅色主题与「去分割线化」都没有新增组件选择器， 只是把原先复用一个值的地方拆成了两个名字，让浅色能单独处置—— --c-border-field / --c-border-float（描边拆成「控件」与「浮层」两种命运）、 --c-fill-field + --c-shadow-lift/float（描边退场后改由填充与阴影承担层级）、 --c-primary-bg / --c-primary-fg（主按钮的底色与前景必须成对换）。 结构分割线则整体消失：rail 右侧、页签底部、卡片四周、表格行间的 --hairline 全部撤掉， 层级交给色差。
