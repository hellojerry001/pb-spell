function renderRail() {
  const rail = $("rail");
  const top = NAV.filter(n => !n.bot).map(UI.railButton).join("");
  const bot = NAV.filter(n =>  n.bot).map(UI.railButton).join("");
  rail.innerHTML = top + '<div class="rail-sp"></div>' + bot;
}

UI.railButton() 产出的按钮：

'<button class="rail-btn" data-page="' + esc(item.key) + '" data-tip="' + esc(item.label) +
  '" data-act="nav"><svg viewBox="0 0 20 20">' + item.icon + "</svg></button>"

注意 data-act="nav"：六个按钮共用同一个动作，靠 data-page 区分目标。 委托层里就一行：

on("nav", el => goPage(el.dataset.page));

类名

类名作用
.rail宽 var(--rail-w) = 64px + --c-rail 底 + z-index: var(--z-rail)。没有右描边——浅色下靠 --c-rail 与内容区的色差分界
.rail-btn40×40 圆角按钮（--r-10），--c-text-3 图标色，position: relative（给气泡与提示圆点定位）
.rail-btn:hover底 → --c-surface-2，图标 → --c-text-2
.rail-btn.is-on底 → --c-surface-4，图标 → --c-text
.rail-btn::after悬浮名称气泡（见下）
.rail-btn.has-dot::before右上角提示圆点（见下）
.rail-spflex: 1，把底部项顶到底

图标：fill / stroke 不写在 svg 上

.rail-btn svg {
  width: var(--icon);          /* 20px */
  height: var(--icon);
  fill: none;
  stroke: currentColor;        /* ← 关键 */
  stroke-width: var(--icon-stroke);   /* 1.6 */
  stroke-linecap: round;
  stroke-linejoin: round;
}

stroke: currentColor 意味着图标颜色跟着按钮的 color 走——hover 与选中态改变 color 之后，图标自动跟着变，不需要为每个状态写一条 SVG 规则。

唯一例外是雷达图标中间那个圆点：它用 fill="currentColor" stroke="none" 单独标在元素上 （实心点比空心圈清楚）。这正是「默认走样式、特例走属性」的用法。

导航图标是 20×20 线性图标，1.6 描边 + round 端点。1.6 而不是 2：在 20px 尺寸下 2px 描边会让圆角矩形看起来发胖。

填充型：fill 必须显式声明

另一类图标是填充型：一条闭合 path，形状本身就是轮廓（比如「关于」页反馈行的跳转箭头 .about-arrow）。它与描边型必须分开处置 —— 它的 fill 同样写在 CSS 里，但值不同：

.about-arrow {
  color: var(--c-text-3);
  fill: currentColor;   /* 不写的话是 SVG 默认的不透明黑，color 完全不起作用 */
  stroke: none;
}
.about-row.is-link:hover .about-arrow { color: var(--c-text); }

这条实测踩过：该规则在改成填充型图标之前只有 color: var(--c-text-3)， 探针读出来是 color = rgba(0,0,0,.34) 而 fill = rgb(0,0,0) —— 两者不一致， 说明 color 连同 hover 变色全是死代码，从来没生效过；箭头一直是纯黑。

排查口诀：填充型 SVG 只要没显式给 fill，color 就是白写的。 验证方式：getComputedStyle(svg).fill 必须与 .color 相等。 （读值时记得先 svg.style.transition='none' —— 否则 transition: color 会让 getComputedStyle 返回动画起始值，看起来像「改了没反应」。）

悬浮名称气泡：自绘不用 title

.rail-btn::after {
  content: attr(data-tip);          /* ← 文案来自 data-tip 属性 */
  position: absolute;
  left: calc(100% + var(--px-12));  /* 浮在 rail 右侧 */
  top: 50%;
  transform: translateY(-50%);
  background: var(--c-tooltip);
  border: var(--hairline) solid var(--c-border-float);   /* 浅色下透明 */
  box-shadow: var(--c-shadow-lift);                      /* 浅色下改由阴影找边界 */
  font-size: var(--fs-11);
  padding: var(--px-4) var(--px-9);
  border-radius: var(--r-7);
  white-space: nowrap;
  opacity: 0;
  pointer-events: none;             /* 不挡鼠标 */
  transition: opacity var(--dur-fast) var(--ease);
  z-index: var(--z-tip);
}
.rail-btn:hover::after { opacity: 1; }

为什么不用原生 title：系统 tooltip 有约 1 秒延迟、样式无法控制、在桌面应用里和整体 深色风格完全不搭。自绘气泡用 content: attr(data-tip) 取文案，所以文案只写在一处（JS 的 NAV 表里），既进了 DOM 属性，也当了无障碍的 title 来源。

pointer-events: none 不能少——否则气泡出现后会挡住相邻按钮的 hover，导致闪烁。

提示圆点：只能用 ::before

「关于」是唯一会自己变化的入口——检测到新版本时，about.js 给它加一个 .has-dot：

.rail-btn.has-dot::before {
  content: "";
  position: absolute;
  top: var(--px-5); right: var(--px-5);
  width: var(--dot); height: var(--dot);      /* 7px */
  border-radius: var(--r-full);
  background: var(--c-text);                  /* 深色近白 / 浅色近黑 */
  box-shadow: 0 0 0 var(--px-2) var(--c-rail);  /* 描一圈 rail 底色的「切口」 */
}

三个点都是踩出来的：

  • 必须用 ::before。 ::after 已经被悬浮名称气泡占了（content: attr(data-tip) + opacity: 0）。挂在 ::after 上的后果有两层：气泡被顶掉（这个按钮再也弹不出名字）， 而且从气泡继承来的 opacity: 0 不会被覆写 —— 圆点根本不可见。 更坑的是这个 bug 骗得过 DOM 断言：类加上了、尺寸也量得到，只有像素扫描能抓到。
  • box-shadow 那圈「切口」不是装饰。 选中态按钮底是 --c-surface-4（浅色下是白）， 圆点直接贴上去会被吃掉。描一圈与 rail 同色的边，静置 / 悬停 / 选中三态都看得清， 而且跟着主题自动换色，不用为主题各写一条规则。
  • 底色用 --c-text 而不是某个表面阶。 表面阶是「叠在底上的半透明」， 圆点要的是「两套主题里都最醒目」——--c-text 正好是这个语义（深色近白、浅色近黑）。

圆点由 about.js 控制，不由 rail.js 渲染：renderRail() 每帧重建按钮， 而圆点取决于「有没有新版本」这个异步结果；写成类名切换就不会被重渲染清掉。

切换逻辑

function goPage(key) {
  if (!PAGES[key]) key = "projects";
  curPage = key;
  $$(".rail-btn").forEach(b => b.classList.toggle("is-on", b.dataset.page === key));
  Object.keys(PAGES).forEach(k => {
    const el = $("page-" + k);
    if (el) el.classList.toggle("is-active", k === key);
  });
  $("pgTitle").textContent = PAGES[key][0];
  $("pgSub").textContent   = PAGES[key][1];
  if (key === "publishes") refreshPublishes();
  document.querySelector(".app-main").scrollTop = 0;
}

页面显隐只靠 .page / .page.is-active 两个类，不写内联 display：

.page { display: none; }
.page.is-active { display: block; }

scrollTop = 0 是最后一行的固定动作：切页时把滚动容器的位置归零， 否则从「发布记录」滚到底再切回「项目管理」会停在一个奇怪的位置。
