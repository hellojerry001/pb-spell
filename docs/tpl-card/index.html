模板卡 TplCard

「从模板新建项目」弹窗顶部的一行选择卡。它同时承担一个隐性职责： 在用户填表之前就把「这个模板会用哪套 Node」摊开。

移动端脚手架
zmi + mzui · H5 移动应用
端口 8200 起 · Node 18.16.0

左为选中（.is-on：底色再亮一阶 --c-surface-6，不靠描边）， 右为 hover。tpl-grid 固定两列 —— 模板就两个，多了会挤。

 * TplCard —— 模板选择卡

 */

    name: "移动端脚手架",
    desc: "zmi + mzui · H5 移动应用",

  },
];

结构

$("tplGrid").innerHTML = scaffolds.map(s =>
  '<div class="' + cls("tpl-card", s.key === tplPicked && "is-on") + '"' +
    dataAttrs({ act: "tpl-pick", key: s.key }) + ">" +
    '<div class="tpl-name">' + esc(s.name) + "</div>" +
    '<div class="tpl-desc">' + esc(s.desc) + "</div>" +
    '<div class="tpl-port">端口 ' + esc(s.portStart) + " 起 · Node " +
      esc(s.nodeVersion || "默认") + "</div>" +
  "</div>").join("");
类名作用
.tpl-grid固定两列（grid-template-columns: 1fr 1fr）+ gap: 10px + margin-bottom: 16px
.tpl-card--c-fill-field 底 + --r-10；cursor: pointer（无描边）
.tpl-card:hover底 → --c-surface-3
.tpl-card.is-on底 → --c-surface-6（比 hover 再亮一阶，选中不靠描边）
.tpl-name--fs-13 + 600 字重
.tpl-desc--fs-11 + --c-text-3
.tpl-port--fs-11 + --c-text-2（比 desc 亮一档——它是决策信息，不是背景描述）

为什么固定两列

内置模板就两个（pc / mobile）。写死 1fr 1fr 比 auto-fill 更稳： auto-fill 在窄弹窗下会塌成一列，两个模板一上一下反而不利于对比。 如果以后模板变多，这里应该改成 repeat(auto-fill, minmax(200px, 1fr)) 并重新验证。

弹窗宽度走 .modal.is-wide（560px），两张卡各约 265px——刚好放得下 「PC 端脚手架」+「zmi + zui · Vue 2 · 门户微应用」这种长度的两行文案。

选中后的连锁反应

async function pickTpl(key) {
  tplPicked = key;
  renderTplGrid();                       // ① 重绘，把 is-on 挪过去

  const s = scaffolds.find(x => x.key === key);
  if (s && !s.nodeReady) {
    setHint("没找到 Node " + s.nodeVersion + "，将退回系统默认版本启动", true);   // ② 警告
  } else {
    setHint("");
  }

  try {
    $("tPort").value = await invoke("suggest_port", { scaffold: key });          // ③ 自动填端口
  } catch (e) { /* 探测失败就留给用户手填 */ }
}

第二行是这套 UI 里少见的主动预警：nodeReady 由后端检查「这台机器上有没有该版本的 Node」， 没有就提前用 hint.is-warn（暖黄）说明会退回系统版本——而不是等创建完启动失败再报错。
