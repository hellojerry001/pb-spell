分类页签 Tabs

项目页顶部的 Web / Mac 分栏 —— 为什么两类项目不该混在一张列表里。

分类页签 Tabs

ui/css/components.css 里的 .tabs / .tab / .tab-count。

Web 分栏选中 —— 计数是当前分栏的项目数
Mac 分栏选中 —— 药丸底色（--c-surface-4），整屏无下划线
三种状态：静置 / hover / 选中
在页面里的位置：页头之下、工具条之上

项目管理

Web 应用 · 端口与浏览器预览
/**
 * Tabs —— 分类页签
 * 结构来自 projects.js 的 renderTabs()：
 * `<button class="tab is-on" data-act="proj-tab" data-kind="web">Web 项目<span class="tab-count">3</span></button>`
 *
 * 用途：项目页要在「Web 项目」和「Mac 项目」两套操作之间切换 ——
 * 前者起 HTTP 服务、用浏览器预览、可发布；后者起原生窗口、产物是 .dmg。
 * 两类项目的字段与操作都不同，混在一张列表里会让每张卡片都要解释自己是什么，
 * 所以用页签先分栏。
 *
 * 选中态是「填了底的药丸」（--c-surface-4），与 rail 图标同一套表达：
 * 选中 = 底色变化，不画线。
 * 不是新造一套「下划线页签」样式。
 *
 * 说明：`pb-show-hover` 是文档专用类，把 hover 声明静态展开（真交互里是 :hover）。
 */

const KINDS = [
  { key: "web", label: "Web 项目", count: 3 },
  { key: "mac", label: "Mac 项目", count: 2 },
];

function TabBar({ active }: { active: string }) {
  return (
    <div className="tabs">
      {KINDS.map((k) => (
        <button key={k.key} className={"tab" + (k.key === active ? " is-on" : "")}>
          {k.label}
          <span className="tab-count">{k.count}</span>
        </button>
      ))}
    </div>
  );
}

export function Demo() {
  return (
    <div className="pb-stack">
      <div>
        <span className="pb-spec">Web 分栏选中 —— 计数是当前分栏的项目数</span>
        <TabBar active="web" />
      </div>

      <div>
        <span className="pb-spec">Mac 分栏选中 —— 药丸底色（--c-surface-4），整屏无下划线</span>
        <TabBar active="mac" />
      </div>

      <div>
        <span className="pb-spec">三种状态：静置 / hover / 选中</span>
        <div className="tabs">
          <button className="tab">
            静置<span className="tab-count">4</span>
          </button>
          <button className="tab pb-show-hover">
            hover<span className="tab-count">4</span>
          </button>
          <button className="tab is-on">
            选中<span className="tab-count">2</span>
          </button>
        </div>
      </div>

      <div>
        <span className="pb-spec">在页面里的位置：页头之下、工具条之上</span>
        <div className="app-main" style={{ padding: 0 }}>
          <div className="page-head">
            <h1 className="page-title">项目管理</h1>
            <span className="page-sub">Web 应用 · 端口与浏览器预览</span>
          </div>
          <TabBar active="web" />
          <div className="toolbar">
            <button className="btn is-ghost toolbar-lead">
              发布记录<span className="btn-count">4</span>
            </button>
            <button className="btn is-ghost">手动添加</button>
            <button className="btn is-primary">＋ 从模板新建</button>
          </div>
        </div>
      </div>
    </div>
  );
}

为什么需要分栏

PortButler 原本只管一类东西：起个 HTTP 服务，用浏览器看，需要时发到线上。 后来多了 Mac 桌面应用（Tauri），差异不是「多一个字段」级别的：

Web 项目Mac 项目
启动后是什么HTTP 服务，监听端口原生窗口，未必监听端口
「打开」的方式浏览器 localhost:<port>它自己就弹出来了
产物静态目录，可发布到 Cloudflare.dmg，本地分发
端口必填，是定位服务的锚点可留空，只在项目顺带跑前端服务时才填

混在一张列表里的代价是每张卡片都得自己解释一遍「我是哪一类」， 而且「浏览器 / 发布」这类按钮对 Mac 项目永远是错的。分栏之后， 每张卡片的操作集合天然正确，不需要在按钮层面做条件禁用。

选中态是药丸，不是下划线

整屏没有任何下划线。选中项是一颗填了底的药丸，未选中项透明—— 与 rail 图标、模板卡用的是同一套「选中 = 底色变化」的表达， 而不是给每个组件各画一条线。

.tab {
  padding: var(--px-6) var(--px-12);
  border-radius: var(--r-8);
  background: transparent;
  color: var(--c-text-3);
}
.tab:hover { background: var(--c-surface-2); color: var(--c-text-2); }
.tab.is-on { background: var(--c-surface-4); color: var(--c-text); font-weight: var(--fw-semi); }

.tabs 容器上也没有 border-bottom。原来那条线身兼两职——既是分隔线， 又是指示短横线的轨道；「去分割线化」时它跟着一起退场了。 省掉它之后页签盒高度少 1px，padding-bottom 也从当初为容纳指示条多留的 9px 收回 6px（几何净变化就是这一处）。

计数角标

.tab-count 是 --fs-10 的小药丸，font-variant-numeric: tabular-nums 让数字等宽， 数字从 9 跳到 10 时页签宽度不会抖。选中时底色升一阶（--c-surface-3 → --c-surface-6）。

与工具栏的分工

页签只回答「看哪一类」，不承担动作。所以工具条留在页签下方， 其中「＋ 从模板新建」在 Mac 分栏下整个隐藏 —— 现有模板都是 Web 脚手架， 留一个点了会建出 Web 项目的按钮在 Mac 分栏里，比没有更糟。
